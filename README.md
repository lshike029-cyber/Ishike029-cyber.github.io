# 电商订单经营与履约质量全链路分析

> 基于销售、品类、区域、卖家、物流、评价与支付数据的 Tableau 风格可视化分析作品集  
> Portfolio for Data Analyst / BI Analyst / Business Analyst internship applications

## 项目定位

这是一个面向数据分析实习投递的个人作品集项目。项目围绕电商平台的两个核心问题展开：

1. 平台整体经营表现如何，收入主要来自哪些品类、地区和卖家？
2. 物流履约是否影响用户评分，哪些品类、地区和卖家存在体验风险？

项目从原始电商订单数据出发，完成数据导入、指标建模、BI 汇总、可视化设计和业务洞察输出。最终产出一个可在线访问的交互式数据分析网站，用于简历展示和面试讲解。

## 数据来源

本项目使用 Olist Brazilian E-Commerce Public Dataset。该数据集包含巴西电商平台订单、客户、卖家、商品、支付、物流和评价等信息，适合进行经营分析、履约分析和用户体验分析。

主要数据表包括：

- orders：订单主表
- order_items：订单商品明细
- order_payments：支付记录
- order_reviews：用户评价
- customers：客户信息
- sellers：卖家信息
- products：商品信息
- product_category_translation：商品品类翻译表

## BI 汇总表设计

为了更适合 Dashboard 分析，本项目在 SQL Server 中生成了 8 张 BI 汇总表：

| 汇总表 | 分析用途 |
|---|---|
| bi_monthly_kpi | 月度订单数、销售额、客户数、客单价、评分、配送天数、延迟率 |
| bi_category_sales | 品类销售额、订单量、卖家数、评分、延迟率 |
| bi_state_sales | 州维度销售额、客户数、订单数、配送天数、评分 |
| bi_payment_analysis | 支付方式与分期期数分析 |
| bi_delivery_analysis | 配送时长分组、平均评分、延迟率 |
| bi_review_distribution | 1-5 星评分分布和不同评分下的配送天数 |
| bi_seller_rank | 卖家销售额、订单数、评分、延迟率 |
| bi_order_status | 订单状态结构 |

## Dashboard 1：经营总览与收入贡献分析

分析目标：

> 平台整体经营表现如何？收入主要来自哪些品类、地区和卖家？

核心指标：

- 总订单数
- 总销售额
- 客户数
- 平均客单价
- 平均评分
- 延迟交货率

主要图表：

- 月度销售额趋势
- 月度订单数与客单价趋势
- Top10 品类销售额排行
- Top10 州销售额排行
- Top10 卖家销售额排行
- 支付方式销售额占比
- 订单状态结构

核心洞察：

1. 平台收入集中在少数核心地区和核心品类，SP、RJ、MG 等州以及健康美容、手表礼品、床品家居等品类贡献较高销售额。
2. 订单状态整体以已送达为主，说明交易履约基础稳定，但取消、不可用等异常订单仍需持续监控。
3. 信用卡及分期支付承载较高支付金额，分期付款可能对高客单价商品转化具有促进作用。

## Dashboard 2：履约体验与风险诊断分析

分析目标：

> 物流履约是否影响用户评分？哪些品类、地区和卖家存在体验风险？

核心指标：

- 平均配送天数
- 延迟交货率
- 平均评分
- 1 星评价数
- 30 天以上配送订单数

主要图表：

- 配送时长对用户评分的影响
- 配送时长分组延迟率
- 用户评分分布
- 不同评分订单的平均配送天数
- 地区销售额与配送效率散点图
- 品类收入与用户评分散点图
- 卖家销售额与履约风险散点图

核心洞察：

1. 配送时长与用户评分呈明显负相关，配送超过 30 天后平均评分明显下降。
2. 低评分订单通常伴随更长配送周期，说明物流体验是差评的重要诱因。
3. 高销售额但高延迟率、低评分的品类、地区和卖家，应作为后续运营优化重点。

## 项目故事线

本项目围绕电商平台的“经营增长”和“履约体验”两个核心问题展开。首先通过月度 KPI、订单状态、品类排行、地区排行和卖家排行分析平台整体经营表现，识别核心收入来源；随后进一步从配送时长、延迟交货率和用户评分切入，分析物流履约对用户体验的影响，并定位高价值但体验风险较高的品类、地区和卖家。最终为平台提出核心市场保障、物流履约优化、卖家分层管理和分期支付运营等策略建议。

## 简历表达

可以在简历中这样描述：

> 基于 Olist 电商订单、支付、物流、评价、品类、地区和卖家数据，使用 SQL Server 构建 8 张 BI 汇总表，并设计电商经营与履约质量分析仪表盘。项目拆分为经营总览与履约诊断两个 Dashboard，展示订单数、销售额、客单价、评分、配送天数、延迟率等核心指标，并通过趋势图、排行图、散点图和分布图分析收入贡献与体验风险。分析发现配送时长与用户评分存在明显负相关趋势，长配送周期订单评分显著下降，为平台物流优化、卖家分层管理和重点市场运营提供依据。

## 面试讲解重点

面试时可以按下面顺序讲：

1. 为什么选择电商数据：订单、支付、物流、评价链路完整，适合做经营分析和体验诊断。
2. 如何建模：先保留原始明细表，再用 SQL Server 汇总出面向 BI 的主题表。
3. Dashboard 1 看什么：整体销售规模、核心收入来源、支付方式和订单状态。
4. Dashboard 2 看什么：配送时长、延迟率、用户评分以及高价值风险对象。
5. 业务结论：物流时效对用户评分有明显影响，后续应优先优化高销售额但体验风险高的地区、品类和卖家。
